visível para clientes e exige validação e uma forma de voltar atrás.

## Código e publicação

- [ ] Manter cópia ou commit da versão atualmente publicada.
- [ ] Fazer as alterações em uma branch separada, após verificar o estado do Git.
- [ ] Não levar `.env`, tokens, senhas, arquivos internos ou dados de clientes.
- [ ] Revisar os arquivos antes de torná-los públicos, inclusive o histórico caso existam segredos antigos.
- [ ] Não adicionar scripts de publicidade, analytics ou terceiros sem revisar privacidade.
- [ ] Verificar os caminhos dos arquivos no endereço de publicação.
- [ ] Definir qual versão restaurar se houver algum problema.
- [ ] Validar a página publicada e os links depois da atualização.

Nenhum comando de exclusão, sobrescrita do site em produção ou envio ao
GitHub acompanha este roteiro. Essa etapa deve ser feita depois da aprovação.
